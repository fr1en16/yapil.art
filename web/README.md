# web.yapil.art

Отдельный сайт веб-направления Yapil, визуальный ориентир — https://armory.framer.ai/.
Собирается независимо от основного сайта. Общие шрифты, логотип и уже опубликованные
медиа используются из существующего проекта и `https://media.yapil.art`.
На обложке используется 20-секундный видеолуп из указанного референса, опубликованный
в Yapil R2. Для первого кадра и режима уменьшенного движения есть статичный WebP-постер.
Шрифт заголовков — Inter Tight без засечек; логотип студии сохранён.

Обложка повторяет композицию Armory: услуги начинаются в верхней правой половине,
бренды располагаются под ними, заголовок с описанием и кнопкой ограничен левой
колонкой шириной до 600 px. На мобильном сначала идут заголовок и кнопка,
затем услуги и бренды. Высота обложки зависит от содержимого и размера окна.

При загрузке заголовок, описание и кнопка мягко поднимаются, услуги появляются
справа с шагом 100 ms. Шапка и бренды дополняют ту же последовательность.
Анимации используют отдельное CSS-свойство `translate`, сохраняя hover-эффекты.
Общее меню раскрывается сверху, ссылки появляются по очереди; закрытие завершается
до перехода по ссылке. Native dialog сохраняет фокус и блокировку прокрутки,
Escape закрывает меню, якорные ссылки переводят фокус в выбранную секцию.
При `prefers-reduced-motion` входные анимации отключены, меню закрывается сразу.

Главная продолжает композицию Armory: узкие смещённые заголовки, светлые строки
кейсов, сетка форматов, визуальная половина процесса и двухколоночный FAQ.
На светлых секциях навигация меняет контраст. `scroll-motion.ts` управляет
проявлением слов при прокрутке, последовательным появлением блоков, раскрытием
изображений и небольшим параллаксом. Обновления сгруппированы через requestAnimationFrame;
настройка уменьшенного движения отключает эффекты. Без JavaScript контент виден.
Иллюстрации направлений и форматов нарисованы HTML/CSS; изображение процесса взято
из уже опубликованного кейса Compass.

Внутренние страницы используют `inner.css`: кейсы начинаются с фотографической
обложки, продолжаются текстовой сеткой и галереей с известными размерами изображений,
а результат и следующий проект переходят на светлый фон. Заявка построена в двух
половинах: заголовок и форма слева, контакты на статичном постере клавиатуры справа.
На мобильном экране половины и поля последовательно складываются в одну колонку.
Поля, валидация, согласие, выбор формата из URL и доставка заявки сохранены.

Видео приостанавливается вне первого экрана и в скрытой вкладке. При настройках
уменьшенного движения и экономии данных видео не загружается, показывается постер.
Происхождение и проверенные URL медиа зафиксированы в `src/data/hero-media.json`.
Для замены видео и постера используйте `scripts/publish-web-hero.mjs`: он загружает MP4,
конвертирует постер в WebP через Tinify, проверяет R2 и лишь затем обновляет ссылки.

```sh
npm run dev:web -- --background
npx astro dev status
npx astro dev logs
npx astro dev stop
npm run build:web
npx astro check --config astro.web.config.mjs --tsconfig tsconfig.web.json
node --experimental-strip-types --test web/worker.test.mjs
```

Просмотр: http://127.0.0.1:4404. В dev-режиме форма проверяет поля, но не отправляет
тестовые обращения в production. Для проверки доставки используйте тесты с подменённым fetch.

Публикация владельцем при настроенном Cloudflare-доступе:

```sh
npm run build:web
npm run deploy:web
```

`wrangler.web.jsonc` создаёт отдельный Worker `yapil-web` с custom domain `web.yapil.art`.
Основной Worker `yapil-astro` не заменяется. Нужны права на Workers и custom domain в зоне
`yapil.art`. Ключи задаются через защищённое окружение или существующую авторизацию Wrangler.

Статика находится в `dist-web`. Worker обслуживает только `/api/*` и передаёт валидные
обращения из формы в существующий `/api/lead` через service binding `LEADS` на Worker
`yapil-astro`, сохраняя источник
`web.yapil.art`. Приватные ключи Telegram и CRM здесь не дублируются. Успех показывается
только после подтверждения доставки основным сервисом.

Workflow `.github/workflows/web.yml` проверяет изменения в Pull Request и публикует веб-направление
после слияния в `master`. Использует существующий environment `production` и его
`CLOUDFLARE_API_TOKEN`; у ключа должны быть права на новый Worker и домен. Основной workflow не изменён.
